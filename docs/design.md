# 디지몬 챔피언쉽 팬게임 — 기획 (3판, 2026-11-12)

디지몬 챔피언쉽(NDS, 2008)의 시스템을 웹으로 다시 구현하는 비영리 팬게임.
디지몬 이름·진화 루트·진화 조건은 공개 공략 위키(나무위키 진화 목록)의 내용을 게임 데이터(`src/data/evolutions.txt`)로 옮겼다.
규칙 엔진은 `src/core`, 화면은 `web/`. 엔진은 `npm run build:core`로 `web/core.js`가 된다.
그림: `web/assets`에 원본 Nitro 리소스에서 변환한 PNG 217장(디지에그 + 진화표 216종 전부). 원본 파일명과 한글 이름 대응은 `tools/sprite_names.json`.

## 원작에서 가져온 규칙
- 세대: 유년기I → 유년기II → 성장기 → 성숙기 → 완전체 → 궁극체 (220여 종)
- 진화 조건: 속성 수치 / 배틀 횟수(승률) / 디지에그화 횟수 / 발병 횟수(페널티). 아무것도 못 채우면 수명이 다할 때 시간 경과 진화
- 표의 위에서부터 검사해 처음 충족하는 쪽으로 진화
- 디지에그화: 완전체 이상이거나 배틀 10회 이상이면 수명이 다할 때 알로 돌아감. 그렇지 않으면 로스트
- 디지에그화를 거칠수록 요구 수치가 조금 줄어듦
- 썩은 고기 두 개를 먹으면 병 (페널티)
- 케이지에 넣어 두면 정해진 능력치·속성이 오르고 반대쪽은 내려감
- 성격 8종, 능력치 HP·TP·공격·방어·지능·민첩
- 배틀은 자동, 출전 전 일반·지원·특수 선택. 프리 배틀, 타이틀 매치, 챔피언십(가을 예선 → 다음 해 본선)
- 사냥: 로프로 둘러 포획, 서식지와 계절
- 시작: 디지에그 → 깜몬

## 플레이 영상으로 확인한 것 (YouTube RmZxzNaH-rs, 한국어판 실기 26분)
화면
- 두 화면 나란히: 왼쪽 아이소메트릭 육각 사육장(운동장 트랙, 보건실, 바닥의 똥), 오른쪽 정보창
- 정보창 상단 띠: 계절 · N일 · 모드(육성/사냥/배틀/상점) · 시각 · 비트. 본문 HP/TP/FP/용량, 보유 디지몬 아이콘 줄
- 배틀: 필드 자동 전투(Auto), 매치 이름·팀 이름·제한 시간 120·HP 막대, 승리 시 WIN과 랭크 업 메시지

진행
- 이름 등록 → 디지에그 이름 → 튜토리얼(부화, 운동장에서 HP 상승, 배고프거나 HP가 줄면 보건실, 자는 동안 사냥)
- 하루는 밤 9시쯤 끝남. 일정표 체크 표시 날이 타이틀 매치
- 첫 타이틀: 봄 3일 '에이스 오브 링', 팀 에이스 1:1
- 타이틀을 딸 때마다 랭크 업. 세 번째 타이틀에서 '레드 테이머': 최대 용량 96G, 케이지 공간 16, 성숙기 진화 허용
- 랭크 업 시 상점 품목 추가 (사냥 도구 등)
- 프리 배틀은 매일 가능, 지면 부상. NPC가 디지몬을 비트로 사겠다는 이벤트
- 사냥: 여러 사냥터, 도망가는 디지몬을 와이어로 막음, 로프로 둘러 당기면 HP가 깎이고 다 깎아야 포획, 성장기는 성장기용 로프 필요, 용량이 차면 놓아줄 디지몬 선택

진화 예 (게임 내 진화표, evolutions.txt와 일치)
- 뿔몬: 가오몬(배틀 3) / 파피몬(짐승 20) / 사이케몬(데이터 10 + 페널티 3) / 에렉몬(시간)
- 아구몬: 그레이몬(배틀 6) / 스카몬(페널티 4) / 티라노몬(시간)
- 레나몬: 구미호몬(짐승 20) / 스카몬(시간), 구미호몬 → 가루다몬(새 40 + 배틀 8)

## 훈련 결과 코드 조사와 적용 (1~4번 후속)
- 적성 후보14바이트(+116~129)는 훈련 전용 적성이 아니다. 사냥 overlay0 0x02112618의13분기에서 +116과+118~129를 읽고 장비 반응을 고른다. +117은 로프 처리 0x02118628/0x02118680에서 사용. 종류별 정확한 명칭을 모두 확정한 것은 아니므로 훈련 배율로 전용하지 않는다.
- 실제 훈련 결과표: ARM9 0x020c87a4, 시설당 포인터4개(16바이트). 앞3개는 확률/항목 개수/(항목,증감) 쌍. 0x0204f268이 누적 확률로 선택하고, overlay18 0x0211d7dc에서각 쌍을 0x02117274로 적용한다. 뒤 포인터는 부가 생활 효과(이번 범위 밖).
- 항목0~10: 바이러스·백신·데이터·용·짐승·물·새·기계·성·벌레풀·암흑. 11~15: 열·추위·천둥·빛·어둠 내성. 16~21: HP·TP·공격·방어·지능·민첩. 표시명은 txt_list #19~40 및 명령 분기/상태 필드로 대조.
- 예: 운동장 기본70%는 HP+50/TP-2, 다음20%는 HP+70/지능-4, 나머지10%는 민첩+6/방어-6. 이 값에 계절과 난수가 추가되므로 매번 같은 수치가 아니다. 화산의20% 결과는 열 내성 상승/추위 내성 감소다. 큰 시설 일괄×2 대신 이 표를 따른다.
- 여름은 원본 가산표0x0209fcf4(HP+10, 나머지+2), 겨울은0x0209fba4(훈련 항목22개 모두0). 난수 폭은0x0209fb34. r을0~99로 뽑아 trunc((2*w-1)*r/100)-w를 더하되 변동0/최종0이면 원작 분기대로 기존값을 남긴다. 여름 보정만으로0이 되면-1. HP는 부호를 보존해10단위 반올림. 시설 모드1/2 배수는 케이지 랭크업 구현 때 연결하며 이번에는 기본모드0.
- 능력치 표의 여섯 값(+52~61)은 능력치 자체가 아니라 곡선 인덱스로 확인. ARM9 초기화0x02061794 이후가 곡선0x020c9528(25행,16바이트간격)을 조회한다. 기본 최소는 curve[index], 최대는 curve[min(index+3,24)]-1(HP만-10). 예: 아구몬 공격30~53, 아르마몬 방어 상한65, 피요몬 민첩 상한65. 종별 훈련 차이는 이 한계에서 발생하며 별도 적성 배율이라고 부르지 않는다.
- 호환 범위: 기존 웹 능력치/진화 보너스/상대 강도 단위는 유지한다. 인덱스 비율을 성향으로 사용하는 기존 근사는 원작 초기화 계산과 다르다. 기존 능력치가 원작 최소 아래 또는 최대 위이면 경계로 강제 이동시키지 않고 실제 증감 방향만 제한한다(저장값 강제 재산정 없음). 따라서 완전한 원작 능력치 체계 이식은 후속 과제다.
- AP 0~99, 내성0~310은 웹판 제한이다. 원작 AP의 최종 정규화/상한은 아직 확정하지 못했다. 내성은 optional resistance로 저장하고 예전 저장은0으로 읽는다. 훈련 결과와 정보창에 내성을 표시하지만 배틀 피해 반영은 아직 없음을 툴팁에 알린다. 알로 돌아가면 비운다.
- 원본 표에 없는33/36/38은 복제 표를 만들지 않는다. 판매 중인 미니 숲33·미니 공장38은 기존 임시 효과 유지, 미니 얼음36은 여전히 비판매. 링 배틀 수+1·부상·피로·15분 1회·수면 중단/재개는 기존 웹 정책 유지.
- 검증: 원본 결과표37종·곡선25행·코드 참조는 tools/extract_training.py와 docs/training-code-audit.json. 확률 경계70/90, 여름 가산, HP 반올림, 종별 상하한, AP 부분 상승/감소, 기존 범위 밖 저장 보존을 검사. 실제 엔진 훈련→이벤트→머리 위 문자열에서 아구몬·피요몬의 한계 차이를 대조. 화면 frame을1초 구동하여10분 진행과 정지를 확인.

- 부화·디지에그: 새 알의 표시는 능력치0. 부화 시 새 종 초기화+재탄생 횟수 보정을 적용. 기존 임시15% 잔여 능력치 보존은 제거했다. 원작 알 내부 능력치와 그 훈련 이월 경로까지 재현한 것은 아니며 해당 부분은 후속.
- 전투: 원본 overlay19 0x021179e4~0x021179f8은 최대HP/TP를 현재HP/TP에 직접 복사. 웹도 hp=stats.hp, tp=stats.tp로 통일하여 기존 HP×3+40/TP+20 중복 배율 제거. 공격 피해·이동·쿨다운·회복 공식과 대회별 상대 배율은 기존 웹판 임시 규칙이며 원작 전투 전체 계산이 확정된 것은 아니다.
- 저장 이전(웹 정책): 각 디지몬에 statVersion:1. 누락된 기존 저장은 결정적으로 초기 중앙값 이상/종별 상한 이하로 한 번 조정한다. 원래 값은 legacyStats에 복사하여 보존. 기존 임시 진화 경로를 역산할 수 없으므로 원작 이월 계산이라고 주장하지 않는다. 기존 알은0으로 옮김. 재고·배치·먹이·훈련 진행·AP·진화 조건·시간·이름·UID는 유지하고, 버전2/localStorage 키도 유지. 재로딩해도 재적용되지 않는다. 이어하기 일지에 한 번 안내.
